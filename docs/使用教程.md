# OPC 使用教程

从零到出一条片子：**看板选题 → 脚本分镜 → 渲染成片 → 发布预检（可选真发）**。
本文所有命令都在仓库根目录执行。

---

## 0. 网页控制台（推荐）

```bash
./webui/start.sh          # 自动开浏览器 → http://127.0.0.1:4180
./webui/stop.sh
```

顶部五个页签，就是整条流水线的五道工序：

| 页签 | 你看到什么 | 能做什么 |
|---|---|---|
| **数据接口** | 外部热门（B 站）与内部数据的原始样本：标题、博主、播放、点赞、互动率、播放/小时、趋势、标签，全部可点回原视频；每条都标注了来源文件 | 「抓取最新数据」跑完整数据流水线（约 1–3 分钟 / 18 万 token）；覆盖情况里会明说抖音、同赛道博主接口还没接 |
| **数据看板** | 6 个 KPI（外部播放/互动、内部期数/播放、今日 token/预算、任务成败）+ 流量流向、热门样本、内部每期表现、token 按步骤、同领域优秀博主、自动计划、数据新鲜度 | 只用来看；数字都带 sourceRef，可回溯到原始 JSON |
| **选题引擎** | 左栏外部推荐 3 个、右栏内部推荐 3 个（标题、置信度、推荐理由、证据、关键词、成本、创作计划），下面是主题库与使用状态（未创作 / 已成片 / 已发布） | 「用这个主题创作」直接进入创作引擎；「重新生成选题」= 抓数据 + 重建看板 + pi 推荐 |
| **创作引擎** | ① 选主题 → ② 写稿 → ③ **人工确认**（口播稿、标题、简介、标签、分镜全可改）→ ④ 渲染成片 | 文稿出来后 **5 秒不动就自动渲染**；点「暂停」会停住，改完点「立即渲染」；成片带横版 16:9 + 竖版 9:16 两张封面，可下载、可直接去发布 |
| **发布引擎** | 成片列表、投稿信息（标题/简介/标签）、7 项预检逐条结果、发布历史（状态 + BV 号 + 错误码） | 「只跑预检」不碰浏览器；「真实投稿」会打开浏览器自动上传、填标签、提交，提交前必须输入「投稿」二次确认 |

一条片子的完整路径：

```text
数据接口「抓取最新数据」→ 数据看板 看方向 → 选题引擎 选一个主题
   → 创作引擎「开始写稿」→ 5 秒内可改 → 自动渲染 → 去发布
   → 发布引擎「真实投稿」→ 扫码 → 拿到 BV 号
```

> 网页只是壳：每个按钮都会在 `workspace/<runId>/console.log` 留完整输出，
> 等价命令行写在 `webui/README.md` 里；关掉网页不影响任何已有产物。

## 1. 一次性准备

```bash
cd ~/Documents/WayToAGI/opc2      # 仓库根
node -v                            # 需 >= 20（实测 v24）
which pi ffmpeg ffprobe            # 三件套必须在 PATH 里
npm install                        # 根依赖（ajv / yaml）
npm --prefix templates/remotion install     # Remotion 渲染依赖
npm --prefix plugins/publishers install     # Playwright 发布依赖
npx --prefix plugins/publishers playwright install chromium   # 只跑一次
```

自检（应当全绿）：

```bash
npm test                 # 75+ 个单元测试
node bin/opc validate-fixtures   # 11 个 fixture 契约校验
node bin/opc config-check        # 配置文件语法
```

## 2. 一条命令出片

```bash
./plugins/publishers/pipelines/run-create-video.sh
```

它做三件事，串成一条流水线：

| 步骤 | skill | 产出 |
|---|---|---|
| 写稿 | `generate-script` | `data/scripts/{runId}/{themeId}/script.md`（口播稿）+ `storyboard.json`（分镜） |
| 出片 | `render-remotion` | `data/productions/{productionId}/final.mp4` + `cover.jpg` + `storyboard.json` |
| 发布 | `publish-bilibili` | 预检 7 项 → 不通过就不上传；通过后写发布记录 |

一次真实运行（2026-10-24，选题来自当天 B 站热门）：

```
runId:    demo-video-2
status:   success
  script    success  attempt=1
  render    success  attempt=1
  publish   success  attempt=1
```

成片：`data/productions/prod_20261024_theme_20261024_001_demo-video-2/final.mp4`
45.0s / 1920x1080 / 30fps / H.264 / 1.03MB，标题「绝区零先导片拆解：3个镜头套路，45秒看懂它为什么燃」。

> 想换选题：`./run-create-video.sh path/to/themes.json`。文件格式就是 `recommend-themes` 的 output.json，
> 默认读 `data/themes/latest.json`。

## 3. 先跑数据段（真实选题）

上面的默认选题是 `data/themes/latest.json`。要拿**当天**的选题：

```bash
node bin/opc run trends-analysis --launcher spawn
```

四步：抓 B 站热门 → 抓自有数据 → 生成看板 → 用 pi 推荐 6 个主题。

产出：

- `workspace/{runId}/recommend/attempt-1/output.json` ← 这就是选题文件
- `dashboard/dashboard.json`、`dashboard/external_trends.json`（看板数据）
- `dashboard/task_status.json`（任务状态）

把新选题接上：

```bash
cp workspace/<runId>/recommend/attempt-1/output.json data/themes/latest.json
./plugins/publishers/pipelines/run-create-video.sh
```

选题长这样（字段含义见 `contracts/themes.schema.json`）：

```
theme_20261024_001  conf 0.87  绝区零先导片拆解：3个镜头套路        45s
theme_20261024_004  conf 0.81  爆款续集：30秒看懂AI动画进阶版      35s
theme_20261024_006  conf 0.72  token超支后，我用一半预算做完一集    55s
```

`generate-script` 默认挑 confidence 最高的一条；也可用 `--theme-id` 指定（见第 5 节）。

## 4. 真发布（唯一的人工节点：扫码）

默认**只预检、不上传**，发布记录会是：

```
status: manual_fallback
error:  PUBLISH_DISABLED  预检通过，但未启用真实投稿
```

预检 7 项：时长 / 文件大小 / 分辨率 / 标题长度 / 标签数 / 敏感词 / 封面存在。
判定用**原始值**（超长会先报错，不会因为偷偷截断而放过），提交用**裁剪值**。

要真的发：

```bash
OPC_PUBLISH_ENABLED=1 ./plugins/publishers/pipelines/run-create-video.sh
```

流程：打开 B 站投稿页 → **等你在窗口里扫码**（300 秒超时）→ 自动上传、填标题/简介/标签/封面 → 投稿 → 抓 BV 号。

成功记录：

```json
{ "status": "submitted", "platformVideoId": "BV1xx411c7cD",
  "url": "https://www.bilibili.com/video/BV1xx411c7cD" }
```

失败语义（全部写进 `workspace/{runId}/publish/attempt-1/output.json`）：

| code | 含义 | 会不会重试 |
|---|---|---|
| `PRECHECK_FAILED` | 预检没过，**没上传** | 不会 |
| `LOGIN_TIMEOUT` | 扫码超时 | 不会 |
| `SELECTOR_NOT_FOUND` | 页面改版，已留截图 `logs/publish/.../failure-*.png` | 不会 |
| `UPLOAD_FAILED` / `NETWORK_ERROR` | 网络/上传失败 | 手动重跑 1 次 |

> ⚠️ 本机 `data/browser-profiles/bilibili` 里已经有一个登录态。删掉这个目录 = 退出登录，
> 下次发布会重新要求扫码。

## 5. 定时跑

`config/schedule.yaml` 里所有 schedule 默认 `enabled: false`（防止误触发）。改成 `true` 后：

```bash
node bin/opc start --interval 30        # 常驻，每 30 秒检查一次
node bin/opc start --once               # 只检查一次（CI 用）
node bin/opc cron-tick --now 2026-10-24T09:00:00+08:00   # 手动触发指定时刻
```

`manual_approval: true` 的 schedule（发布类）不会被 daemon 自动执行，需要人工放行。

## 6. 逐步手动跑（排障用）

```bash
# 1) 写稿：pi 写 draft.json，脚本校验后组装
node bin/opc run-step --skill generate-script \
  --input data/themes/latest.json --run-id my-1 --launcher spawn
#   → workspace/my-1/generate-script/attempt-1/output.json

# 2) 渲染：吃上一步的 output
node bin/opc run-step --skill render-remotion --id render --contract production \
  --input workspace/my-1/generate-script/attempt-1/output.json --run-id my-1 --launcher spawn

# 3) 预检（dry-run，不开浏览器）
node plugins/publishers/bilibili/publish.mjs \
  --input workspace/my-1/render/attempt-1/output.json --dry-run

# 4) 换一条选题（confidence 最高之外的）
node skills/generate-script/scripts/assemble.mjs \
  --input data/themes/latest.json --draft draft.json --theme-id theme_20261024_006
```

指定 `--run-id` 后可以反复 `node bin/opc attempts my-1` 看每个 attempt 的状态和 token 消耗。

## 7. 产物地图

```
data/
  scripts/{runId}/{themeId}/      script.md / storyboard.json / themes.json
  productions/{productionId}/     final.mp4 / cover.jpg / storyboard.json
  themes/latest.json              当前选题（选题 → 创作的交接文件）
  browser-profiles/bilibili/      发布用浏览器登录态
dashboard/                        看板数据（B 产出）
workspace/{runId}/{step}/attempt-N/
  input.json output.json artifacts.json error.json envelope.json
  run.sh run.pid events.jsonl stderr.log     ← 每一步都可复现、可审计
logs/{runId}/{stepId}/step.log.jsonl         ← 结构化步骤日志
data/token_ledger.jsonl                      ← 每次调用的 token 账本
```

看某一步为什么失败：

```bash
cat workspace/{runId}/{step}/attempt-1/error.json
tail -50 workspace/{runId}/{step}/attempt-1/stderr.log
node bin/opc attempts {runId}
```

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `契约不存在: contracts/xxx.schema.json` | step 的 `contract` 写成了文件路径 | 只写契约名（`production` / `publish-record`） |
| `OUTPUT_MISSING` | skill 没写 `output.json` | 看 `stderr.log`；skill 失败时只写 `error.json` 也算正常，但 code 要对 |
| `OUTPUT_INVALID` | 产物不符合契约 | `node bin/opc validate <契约> <file>` 看具体字段 |
| `DURATION_MISMATCH` | 分镜总时长和主题 `brief.durationSec` 差超 20% | 让 pi 重写 draft，或改用别的主题 |
| 渲染报 `ffmpeg not found` | PATH 缺 ffmpeg | `export PATH="$HOME/.local/bin:$PATH"` |
| 发布 `PUBLISH_DISABLED` | 没开 `OPC_PUBLISH_ENABLED=1` | 这是**预期行为**，不是故障 |
| 发布 `SELECTOR_NOT_FOUND` | B 站投稿页改版 | 打开截图，改 `plugins/publishers/bilibili/platform.json` 的选择器 |
| 单步 token 特别高 | SKILL.md 写太松，pi 自己去翻仓库 | 看 `logs/.../step.log.jsonl` 的 WARN；正常：写稿 5 万内、渲染/发布 1 万内 |

## 9. 三个 AI 各自改哪里

| 角色 | 目录 | 职责 |
|---|---|---|
| A-core | `bin/` `scheduler/` `config/` `contracts/step-envelope*` | 调度、隔离、重试、账本 |
| B-data | `plugins/data-sources/` `skills/fetch-*` `skills/build-dashboard` `skills/recommend-themes` `dashboard/` | 抓数据、看板、选题 |
| C-media | `skills/generate-script` `skills/render-remotion` `skills/publish-*` `plugins/publishers/` `templates/remotion/` | 创作、渲染、发布 |

C 的流水线定义在 `plugins/publishers/pipelines/create-video.yaml`（用 `--pipeline-config` 加载，不占用 A 的 `config/pipeline.yaml`）。
若要并进主配置，把该文件里的 `create-video` 段整体粘到 `config/pipeline.yaml` 的 `pipelines:` 下即可。
